# Programming jobs

Knowing how to program opens the door to many different jobs: this page describes the main ones in simple words, with the languages of this site that go with them and an idea for a first project to try.

> **Goals:**
>
> - discover ten programming jobs and what people do in them during a day;
> - know which languages of this site lead to each job;
> - have an idea for a first project for each one;
> - know how to get started: small projects, GitHub, reading code;
> - know the training paths and the qualities that matter.

## One skill, many jobs

Think about cooking. A pastry chef, a restaurant chef and a baker
all know how to cook. But their days are very different.

Programming is the same. The basics are the same everywhere:
[variables](variables.md), [conditions](logique.md),
[loops](boucles.md), [functions](fonctions.md). What changes is
**what you build** and **for whom**.

For each job, you will find:

- **the day**: what you do, in simple words;
- **the languages** of this site that go with it;
- **a first project** to try at home.

> **Remember:** you don't have to choose your job now.
> Try several small projects: you will see what you enjoy.

## Front-end developer

**The front-end** is the part of a website that you **see**: the pages,
the buttons, the menus. It is the shop window.

- **The day**: turning a mockup (a drawing of the page) into a real
  page. Making a button clickable. Checking that the site works on a
  phone. Fixing a menu that displays badly.
- **The languages**: [JavaScript](../javascript/introduction.md), then
  [TypeScript](../typescript/introduction.md), with
  [HTML](glossaire.md#html) and CSS (see [the web](web.md)).
- **A first project**: a "shopping list" page where you add and
  tick off items.

## Back-end developer

**The back-end** is the **hidden** part: the [server](glossaire.md#server)
that stores the data and answers requests. It is the restaurant's
kitchen, which the customer never sees.

- **The day**: writing the code that saves an order. Building an
  [API](glossaire.md#api) (a counter where other programs ask their
  questions). Organizing the [databases](bases-de-donnees.md).
- **The languages**: [Python](../python/introduction.md),
  [Go](../go/introduction.md), [Ruby](../ruby/introduction.md),
  JavaScript with Node.js, or [Rust](../rust/introduction.md).
- **A first project**: a small server that sends back a random quote
  when someone visits an address.

## Full-stack developer

**Full-stack** means "the whole stack": the front-end **and** the
back-end. This is the person who runs both the shop window and the kitchen.

- **The day**: adding a feature from start to finish. For example,
  the "Like" button: the button in the page, and saving the
  "like" on the server.
- **The languages**: JavaScript and TypeScript on both sides, or
  JavaScript in front and Python, Ruby or Go behind.
- **A first project**: a guestbook. Visitors write a message
  in a page; the server keeps it; the page shows all the messages.

## Mobile developer

They create the **apps** on your phone.

- **The day**: building a screen of the app. Testing on
  several phones. Publishing an update on the app stores.
- **The languages**: the languages of this site are mostly for learning
  the basics. The job often uses Kotlin (Android) or Swift (iPhone).
  With JavaScript or TypeScript, tools like React Native create
  apps for both.
- **A first project**: a timer for cooking pasta.

## Data and artificial intelligence

You work with **data**: tables of numbers, texts,
images. You ask them questions. Sometimes, you teach a
program to recognize things (that is AI).

- **The day**: cleaning a data file full of gaps. Making a
  chart. Answering a question like "Which product sells best
  on Saturdays?".
- **The languages**: [Python](../python/introduction.md), by far,
  plus SQL, the language of [databases](bases-de-donnees.md).
- **A first project**: reading a file of your expenses and computing the
  total per category.

## DevOps and cloud

**DevOps** mixes "development" and "operations". These people make
sure programs **run well**, day and night, on servers rented
online (the **cloud**). They are the guardians of the machine room.

- **The day**: automating putting a site online. Monitoring the
  servers. Reacting when a service goes down.
- **The languages**: [Go](../go/introduction.md) (many cloud tools
  are written in Go), [Python](../python/introduction.md), and the
  [terminal](terminal.md) every day.
- **A first project**: a script that checks every minute that a
  site answers, and shows an alert if it doesn't.

## Embedded developer

**Embedded** code runs inside objects: a washing machine, a
car, a thermostat, a watch. The machine is small, with little
[memory](glossaire.md#ram).

- **The day**: making a light blink at the right moment. Reading a
  temperature sensor. Finding out why the device restarts on its
  own.
- **The languages**: [Rust](../rust/introduction.md) (more and more),
  and C, widely used in this job.
- **A first project**: with a small, cheap electronic board,
  turning on a light when it gets dark.

## Video game developer

They write the **rules** of the game: how the character jumps, what
happens when it touches an enemy, how the score goes up.

- **The day**: tuning the height of a jump. Fixing a character that
  walks through a wall. Making the game smoother.
- **The languages**: big studios often use C++ or C#. To
  start, [JavaScript](../javascript/introduction.md) (games in the
  browser), [Python](../python/introduction.md) or
  [Rust](../rust/introduction.md) are enough.
- **A first project**: "Guess the number" in the terminal, then a
  small snake game.

## Computer security

You **protect** programs and data against attacks. This is the
locksmith of computing: they look for badly locked doors before the
burglars do.

- **The day**: reviewing code to find weaknesses. Testing a site
  the way an attacker would, with permission. Explaining to the team
  how to fix things.
- **The languages**: [Python](../python/introduction.md) for small
  tools, and being able to **read** many languages. Read the
  [security](securite.md) page.
- **A first project**: a program that says whether a password is
  weak or strong.

## QA and testing

**QA** stands for *quality assurance*. You check that
the software **does what it promises**, before the users do.

- **The day**: writing automated [tests](glossaire.md#test).
  Trying the software in every possible way, even strange ones. Writing
  clear [bug](glossaire.md#bug) reports.
- **The languages**: [Python](../python/introduction.md),
  [JavaScript](../javascript/introduction.md) or
  [TypeScript](../typescript/introduction.md), depending on the project being tested.
- **A first project**: writing five tests for a function that computes
  an average. What happens with an empty list?

> Do both first projects this week, in one hour each.
> Which one made you want to keep going?

## How to get started

### Small projects, not a big one

A **portfolio** is a showcase of your projects. Five small, finished
projects are worth more than one big abandoned project.

```text
Week 1   → a temperature converter
Week 2   → a to-do list in the terminal
Week 3   → "Guess the number"
Week 4   → a web page with a button
Week 5   → redo one of the projects, better
```

See also [small projects, by level](apprendre.md#small-projects-by-level).

### Put everything on GitHub

Put each project on GitHub (see [Git](git.md)), with a `README.md`
that says in three lines:

- what the project does;
- how to run it;
- what you learned.

People who hire often look at these pages.

### Read other people's code

You learn to write by reading. Open a small project on GitHub and read
a file. Then try to [contribute](open-source.md) to it.

> **Remember:** small, finished projects visible on GitHub
> show what you can do better than a long speech.

## Training paths

There is no **single** right path. There are three main ones, and many
people mix them.

| Path | How | Strengths | Watch out for |
|---|---|---|---|
| **School** (university, college, engineering school) | Several years of study | Solid basics, a degree, internships | Long; often means starting young |
| **Career change** (bootcamp) | A few months, often for adults | Fast, supervised, in a group | Very intense; check the program and reviews from former students |
| **Self-taught** (on your own) | Books, sites like this one, projects | Free or almost, at your own pace | You need to be regular; nobody guides you |

Let's be honest: no training **guarantees** a job. Be wary
of those that promise one. What matters is what you can
**do**, and what you can **show**.

## The qualities that really matter

Programming also means working with people. These qualities matter
as much as the code:

- **Asking questions.** Saying "I don't understand" is a strength.
  See [asking a good question](apprendre.md#asking-a-good-question).
- **Writing clearly.** A commit message, an issue, some
  documentation: you write a lot.
- **Staying calm in front of a bug.** Read the message, search, try. See
  [reading an error message](lire-une-erreur.md) and [I'm stuck](bloque.md).
- **Being curious.** Tools change; you learn all your life.
- **Accepting feedback.** A code review helps, it doesn't judge.

## Common mistakes

Here, no code mistakes: **false ideas** that discourage
many beginners.

### "You have to be good at math"

False for most jobs. Front-end, back-end, mobile or
testing mostly require **logic**: breaking a problem into
small steps. Additions and percentages are often enough.

Math matters more in a few fields: AI, 3D games,
some security tools. And it can be learned too, little by little.

### "You have to know everything before applying"

Nobody knows everything, even after twenty years in the job. A job offer
often lists many things: it is a wish list, not a list of
requirements.

Fix: if you have the basics and a few projects to show,
apply. You will learn the rest on the job.

### "You have to have started as a child"

Many developers started at 25, 35 or 45, after another
job. That other job is even an advantage: you already know a
field (health, retail, teaching…).

### "You have to know the best language"

There is no best language, only languages suited to a
task. See [which language to choose](choisir.md). After the first one, the
next ones are much faster to learn.

## Test yourself

**1.** What is the difference between the front-end and the back-end?

> **Answer**
>
> The front-end is the part you see (the pages, the buttons). The
> back-end is the hidden part (the server, the data). Full-stack
> does both.

**2.** You like numbers and charts. Which job and which
language of this site should you try first?

> **Answer**
>
> Data, with Python. First project: read a file of expenses and
> compute the total per category.

**3.** You are not good at math and you only have three small
projects. Should you wait before looking for an internship?

> **Answer**
>
> No. Most jobs mostly require logic, and nobody
> knows everything. Put your projects on GitHub with a clear README, and
> apply.

## Summary

- The basics of programming are the same for every job; what changes is what you build.
- Front-end (what you see), back-end (what is hidden), full-stack (both), but also mobile, data, DevOps, embedded, games, security and testing.
- To get started: small, finished projects, on GitHub, with a README.
- School, career change or self-taught: no path guarantees a job; what you can show is what counts.
- Asking questions and writing clearly matter as much as the code.
